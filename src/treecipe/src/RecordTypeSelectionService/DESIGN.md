# Saved record type selections — design notes

Design notes moved out of CLAUDE.md (#563). Read this before changing the service; CLAUDE.md keeps only the rules every change must follow. History is in CHANGELOG.md.

- **A record type selection is SAVED only from the Record types section, and a saved one is DROPPED, never partly applied, when it goes stale** (#196) — **Remember this selection** (unticked by default and with every model) makes `insertTree` carry `isRemembered: true` beside its `recordTypeSelection` (#623; `regenerateWithRecordTypes` did before), and the host writes `recordTypeSelections` plus `recordTypesWhenSelectionSaved` (every record type each object had in the model on screen, host-derived, never posted) through `RecordTypeSelectionConfiguration.saveRecordTypeSelections` when the generate runs, after the confirmation and every guard, never on Cancel; what is saved is every object with a choice (`RecipeCockpitRecordTypeRecipe.planGeneration` over every object of the model), so every object ticked back to its default is an empty selection, which removes both keys, and a failed save warns and still generates. Generate Treecipe reads it (`RecordTypeSelectionConfiguration.readSavedRecordTypeSelection`) only when its options carry NO `recordTypeSelection` key (`hasRecordTypeSelectionOption`), so the section's explicit choice, and Use defaults' `{}`, always win. `SavedRecordTypeSelection` overrides `RecordTypeSelection.resolve` (the instance method `resolveForObject` delegates to), so the check rides the walk that already loads record types: an entry naming a record type the object's WRITABLE map lacks is dropped whole (default block, no IGNORED TODO), and the walk records missing objects and record types added since. One warning per distinct text per session (`showRecordTypeSelectionWarningOnce`), every name escaped, with **Change record types**, which runs `treecipe.openRecipeCockpit` `{ focusRecordTypes: true, objectApiName? }`. `readRecordTypesFocusRequest` keeps only that shape and an api name; the open loads the NEWEST run and `resolveRecordTypesFocus` picks the first card listing the object, with `focusTree.recordTypes.objectApiName` set, and the panel opens the section and scrolls that object's row into view (#321). A focus that scrolled is not scrolled back by `restoreScroll`, and a restored Treecipe search hiding the row is cleared first. The focus rides on every replay as `openFocusTree` until `rendered`, since an open posts before the document's `ready`

- **The saved selection is read and written by `RecordTypeSelectionConfiguration`, never by `ConfigurationService`** (#574) — `ConfigurationService` is the platform layer and reads `treecipe.config.json` without knowing what a record type selection is; `RecordTypeSelectionConfiguration` sits beside `SavedRecordTypeSelection`, uses `ConfigurationService.getTreecipeConfigurationDetail` and `getTreecipeConfigurationFilePath`, and shows each distinct warning once per session. `SavedRecordTypeSelection.ts` stays free of `vscode`.
