# Scratch org service — design notes

Design notes moved out of CLAUDE.md (#563). Read this before changing the service; CLAUDE.md keeps only the rules every change must follow. History is in CHANGELOG.md.

- **"+ New scratch org" decides everything on the HOST, CREATES ONLY, and never deletes an org** (#200, #279, #358) — the panel's `createScratchOrg` carries NO payload: the Dev Hub, the definition file, the alias and the result file are all the host's, and the result file is opened only by the notification's **View output** (#301). It runs `sf org create scratch` and NOTHING else (#358): `ScratchOrgService` builds no deploy argv (a test scans it, and the cockpit's run is asserted to start only the create and the re-list), and the created org's notification offers **Copy deploy command** (`ScratchOrgService.buildSourceDeployCommandText(username)`, clipboard only, never run) beside **View output**. Because nothing is deployed, a scratch org run no longer holds Retrieve validation rules or Generate permission set, nor is held by a retrieve; it still holds, and is held by, everything that touches the org selection, the Troubleshooting tab's deploys (#346) included. `readDeployComponentCounts` and `SCRATCH_ORG_DEPLOY_MAX_BUFFER_BYTES` stay in `ScratchOrgService` for those deploys. The plan is resolved by `ScratchOrgService.resolveScratchOrgPlan` BEFORE the modal and refused before any process — `sfdx-project.json` through the strict `SfdxProjectService.resolveDeployablePackageDirectoryPaths` and `config/project-scratch-def.json` through `isPathContainedInWorkspace` and an `isFile` check, both BEFORE the Dev Hub is asked for, so an unusable project opens no picker; the plan names no package directory and no `replacements`, which only a deploy applies. The Dev Hub is then PICKED, every run, even when only one qualifies (#243): `SalesforceOrgService.listDevHubOrgDetailsForPicker` lists authorizations whose `isDevHub` is exactly `true` and that the CLI reports connected (the same fail-closed check every org picker uses), through the busy quick pick, and a dismissed picker is a quiet cancel. The CLI's default is listed first, labelled `(default)` and carries its `configSource`, and is never chosen for the reader; the modal says where the setting came from only for that one. `--target-dev-hub` is the picked USERNAME, since an alias can be re-pointed between the pick and the run. The ALIAS is the reader's (#279): after the Dev Hub, `resolveScratchOrgPlan`'s `chooseAlias` opens a host `showInputBox` that starts EMPTY, with no `treecipe-` default. Escape is a quiet cancel, and the alias is checked by `ScratchOrgService.validateScratchOrgAlias` (a usable target-org identifier, a usable `OrgOperations` folder name, starting with a letter or digit, no trailing `.` — Windows strips it from a folder name — no Windows device name (`WINDOWS_RESERVED_FOLDER_NAME_PATTERN`), no `@`, at most 80 characters) in the box AND again in the plan, which throws before any process. After the alias, `chooseDurationDays` (#534) opens a second `showInputBox` for the LIFETIME, starting on `SCRATCH_ORG_DURATION_DAYS` (7) and stating the 1 to `SCRATCH_ORG_MAX_DURATION_DAYS` (30) range; Escape is a quiet cancel, and the TEXT is held by `ScratchOrgService.validateScratchOrgDurationDays` (digits only, no sign, decimal, leading zero or space) in the box AND again in the plan, which throws before any process. The plan's `durationDays` is the CLI's `--duration-days`, `scratchOrgCreate`'s `durationDays`, the confirmation's `Duration: N days` line and a `durationDays` field in both paths' result files. An alias another authorized org holds (`SalesforceOrgService.listAliasHolders`, which reads local authorizations only, into a `Map`) is a WARNING-severity validation message, escaped like a notification, never a refusal. The plan carries it as `aliasHolderUsername` and the modal names the move. Because the reader picks the alias, the copied deploy command targets the USERNAME the create answered with, never the alias. The default is read by `readDefaultDevHubIdentifier` from `SF_TARGET_DEV_HUB`, the project's `.sf/config.json`, then the global one IN PROCESS. It is not `sf config get`, because the modal names the Dev Hub and Cancel must start no process; it is not `ConfigAggregator`, which finds the project from `process.cwd()`, and the extension host's cwd is not the workspace. The create goes through `runSalesforceCli`'s PROJECT mode (`ISalesforceCliProjectOptions`): the workspace is the `cwd`, because the CLI reads `sfdx-project.json` from where it runs. A `cwd` the repository controls is a planting ground, though: on Windows `cmd.exe` finds a committed `sf.cmd` (and an npm shim a committed `node`) before PATH. So project mode runs the ABSOLUTE path from `findSalesforceCliOnPath` (relative, empty and in-workspace PATH entries skipped) with `NoDefaultCurrentDirectoryInExePath=1` on Windows, and the definition file is passed RELATIVE. Never add a `cwd` to a CLI call outside project mode. `ERR_CHILD_PROCESS_STDIO_MAXBUFFER` is a STRING code like a spawn errno, and it is `isOutputTooLarge` (a CLI that ran): a create whose answer outgrew the buffer is reported as possibly created, never as not started. Saved results go through `redactSecrets` (the create's `authFields` carry an access token) and `OrgOperations/` gets a `.gitignore`. The modal names what the REPOSITORY decides (the Dev Hub's config source, the definition's admin), each value through `toSingleLine`. The `--json` is untrusted: created only on `status === 0` with a usable username. Result files go to `treecipe/OrgOperations/<username>/<yyyyMMdd-HHmmss>-<operation>.json` (`<alias>/` when no username exists yet), the folder name refused if it carries a separator or is `.`/`..`, the path refused unless contained. Once a username exists the org is KEPT, a cancel that landed as the create succeeded included (`created`); the cockpit then calls `clearConnectedOrgStatusCache` and re-lists through `loadDataOrgs(…, keepUnlistedUsername)`, so the new org is selected by username from a FRESH connection check, and an org not listed yet is neither forgotten nor replaced by another. One run per window, and its state is the window's: `isScratchOrgSetupInFlight` and `scratchOrgRunStateMessage` are static, a panel state built mid-run adopts the run state (`adoptScratchOrgRunState`), and every state is posted to whichever panel is open NOW. While `scratchOrgStateMessage.isRunning` the router refuses a second run, `insertTree`, `selectDataOrg`, ⟳ and `loadDataOrgs` (a second listing would discard the run's own and forget its org), and the panel holds the button, the dropdown, ⟳ and every **+ Create** disabled whatever a listing draws meanwhile. The state message is stored, carried across a reopen and replayed, and posted LAST, after the re-list. A failed create is `showErrorMessage`, never a warning; error notifications go through `escapeForNotification` and are not awaited, so the run ends without waiting for a click. Nothing builds an `sf org delete` argv, and a test scans the source for one. The confirmation offers TWO buttons (#507, a decision on the issue: a choice, not a replacement): **Create with Salesforce CLI** (`RECIPE_COCKPIT_SCRATCH_ORG_CONFIRM_LABEL`), everything above, and **Create with @salesforce/core** (`RECIPE_COCKPIT_SCRATCH_ORG_LIBRARY_CONFIRM_LABEL`), `ScratchOrgService.runScratchOrgSetupWithLibrary`: the Dev Hub opened by USERNAME (`Org.create`, `determineIfDevHubOrg(true)`), `scratchOrgCreate` with the plan's alias and duration and `setDefault: false`, which saves the authorization and alias where the CLI keeps them. `scratchOrgCreate` reads `sfdx-project.json` and project config from `process.cwd()`, which is not the workspace, so the button is offered only when `findLibraryCreateRefusal` finds nothing it would miss (`signupTargetLoginUrl`, `oauthLocalPort`, package ancestors, `SCRATCH_ORG_LIBRARY_UNREAD_PROJECT_CONFIG_KEYS` in `.sf/config.json`/`.sfdx/sfdx-config.json`, or a working directory inside ANOTHER project), the refusal named in the confirmation; the namespace is handed over in `orgConfig` (`buildLibraryOrgConfig`). Its poll cannot be stopped, so its progress has no Cancel. The username is caught from the `authenticate` lifecycle event (one listener, `SCRATCH_ORG_LIBRARY_LIFECYCLE_LISTENER_ID`), and only when `isOwnScratchOrgRequest` finds its ScratchOrgInfo Id in the library's `ScratchOrgCache` with this run's alias and Dev Hub, because Lifecycle is one object shared by every extension in the host; a throw after it is `created` with `incompleteMessage` (kept, selected, a warning naming `sf org resume scratch --job-id`). Its result file goes through `redactSecrets` too
