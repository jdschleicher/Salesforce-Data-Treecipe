# Directory processing — design notes

Design notes moved out of CLAUDE.md (#563). Read this before changing the service; CLAUDE.md keeps only the rules every change must follow. History is in CHANGELOG.md.

- **Generate Treecipe reports through a vscode-free port, and a cancel is not an error** (#216) — the command runs inside one cancellable `ProgressLocation.Notification` and hands `DirectoryProcessor` an `IRecipeGenerationProgress` (`report`, `isCancellationRequested`). `processDirectory` checks for a cancel before each directory it enters, and `processAllObjectsAndRelationships` checks again after the walk and after the trees are built. The command checks after the global value sets load and once more before writing, and never after that, so a run folder is written whole or not at all. A cancel throws `RecipeGenerationCancelledError`, which the command answers with an information message and NEVER routes to `ErrorHandlingService`. It still returns normally, which is what lets the Recipe Cockpit's Generate Treecipe button reload. "N of M" counts the top-level directories of the configured objects path, so the total is known before the walk descends. A walk run without a port behaves exactly as before

- **Every folder is read in name order, whatever order `readDirectory` lists it in** (#592) — `DirectoryProcessor.readDirectoryInNameOrder` sorts by UTF-16 code unit (`RecordTypeService.compareByCodeUnit`, so `<`, never `localeCompare`), once, where the walk reads. It serves the object walk, the field walk and the validation rule walk. Without it the file system's order renumbered relationship trees, moved objects between trees, reordered fields and changed seeded faker-js data, so two machines wrote different recipes from one repository. Upper case sorts before lower case (`Beta__c`, `Zeta__c`, `alpha__c`), an order NTFS and APFS do not list in. `orderControllingFieldsBeforeDependents` (#462) and the compound-field expansion still run after the field walk. `GlobalValueSetSingleton` sorts its listing with `<` too (two files in one folder never share a name, so its comparator has no equal case), and registers every set's full name before any `masterLabel`, so one set's label can never take another set's own name. `DirectoryProcessor.directoryOrder.test.ts` and the golden test's reversed runs hold this

- **A person's compound `Name` is told from a plain one by its object, never by `<type>`** (#114) — a retrieve writes every standard `Name` field file with no `<type>`: the read-only compound on Contact, Lead and Individual, and the writable one on Account, Opportunity, Product2 and Pricebook2. `PersonNameObjects.objectApiNames` (`ObjectInfoWrapper/PersonNameObjects.ts`, imports nothing) is the whole list; it sits below this service because `SOQLTemplateService`, which this service imports, reads it too. A compound `Name` takes the same expansion path as Address and Geolocation (`buildCompoundComponentFieldInfos`), so it leaves no `FieldInfo` of its own and its dedupe drops a part the standard field map or the object's own field file already writes: Contact gains nothing, Lead gains `Salutation`, Individual gains all three. Account is not listed, because only a person account's `Name` is compound and source metadata does not say which an Account is. `User` is not listed either. With no `Name` in `Fields`, the Mermaid ERD no longer shows `Name` for these objects, and `SOQLTemplateService.getCompoundNameFieldNames` selects it straight after `Id`, since it can still be read. A validation rule naming the compound `Name`, or a part the expansion wrote, has no `FieldInfo` carrying rule constraints, so `buildCompoundNameRuleNotAppliedReason` gives it its own reason ahead of `RecipeService.buildMissingFieldReason`, whose "not read from the fields folder" would be false; the rule is still not applied to the part's value

- **A standard compound address is told by its object and name, never by `<type>`, and is written whether or not it was retrieved** (#694) — a retrieve writes every standard address field file (`BillingAddress`, `QuoteToAddress`, Lead's `Address`) with no `<type>` and no `<label>`, so `isCompoundAddressField` also looks the field up in `StandardCompoundAddressFields` (`ObjectInfoWrapper/`, imports nothing; `SOQLTemplateService` reads it too). A project usually has no file for them at all, so `buildUnretrievedStandardAddressFieldInfos` adds each listed address the walk did not find, and both go through `buildCompoundComponentFieldInfos`: a part the standard field map writes (Account, Contact, Lead, faker-js's Contract) or the object's own field file (`Quote/fields/BillingCity`) is written once, so those objects gain nothing and lose the `### TODO` line (and the `null` faker-js put in the data set) their typeless address file used to write. A person account's `PersonMailingAddress`/`PersonOtherAddress` is the exception: it is written only from its own file, since a business account insert, or an org without person accounts, refuses those parts. The parts' labels come from the list, because a typeless file parses with the label `AUTO_GENERATED`. The SOQL templates still select each compound address after the fields, since it can be read: a person account's only when its parts are recipe fields.

- **A validation rule on a part a compound expansion wrote names the compound field** (#697) — an expanded part has no `FieldInfo` carrying rule constraints, so `RecipeService.buildMissingFieldReason`'s "not a field Treecipe read" would be false for it. `buildCompoundComponentFieldInfos` records each part's compound field in `compoundFieldApiNameByPart`, a `WeakMap` so nothing reaches the serialized `treecipeObjectsWrapper` JSON, and `buildCompoundPartRuleNotAppliedReason` reads it: `QuoteToCity is written as a part of Quote's compound QuoteToAddress, which validation rules do not change`. It runs after the read-only and Name reasons and before the missing-field one, so a part the standard field map writes keeps its standard-field reason. The rule is still not applied to the part's value. The part api names come from `ObjectInfoWrapper/CompoundComponentApiName.ts` (imports nothing), so `SOQLTemplateService` reads the same rule without loading `RecipeService`.
