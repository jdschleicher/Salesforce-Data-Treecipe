# Run artifacts — design notes

`RecipeCockpitRunArtifacts` imports only `SfdxProjectService`, so it sits at layer 0 (#572) and `VSCodeWorkspace`, `ScratchOrgService` and the Recipe Cockpit import it from below them. The class keeps its cockpit name. Read this before changing where run files go.

## Where a run's files live

- **A tree's run files live with its recipe, in `GeneratedRecipes/<run>/<tree folder>/RunArtifacts/`, and nothing reads them as a recipe** (#470, a decision on the issue: under the RUN folder, so the files of one run stay with the recipe they were made with and a regeneration starts a new folder, the way a data set records its run) — `RecipeCockpitRunArtifacts` (no vscode) is the one rule: `resolveTreeLocation` (run and tree plain names, both real folders and not links, inside the workspace) and `RecipeCockpitService.resolveTreeRunArtifactsLocation` (the run ON SCREEN and the card's folder; a card with no folder gets none and its writer writes nothing). The tree-scoped writers take that location, never a workspace root: the Troubleshooting deploys and their package.xml, the four retrieves, the permission set assign (`RunArtifacts/OrgOperations/<username>/`, through `ScratchOrgService.writeOrgOperationResult`'s optional location), Generate permission set's record (`RunArtifacts/PermissionSets/<ts>-permission-set-generate.json`, `RecipeCockpitPermissionSetGenerate.writeGenerateResult`; a failed write changes nothing it reports), the Adapter's retrieve staging (`RunArtifacts/OrgOperations/<username>/<ts>-adapter-retrieve[-n]`, still under `treecipe/` so `toOutputDirectoryArgument` accepts it), update snapshots and results (`RunArtifacts/UpdateAttempts/`) and query exports (`RunArtifacts/QueryResults/`). Runs tied to no tree stay in `treecipe/OrgOperations` (scratch org creation; org open writes nothing), and files written before #470 stay where they were: no migration. `makeFolder` makes each segment from the tree folder down one at a time (`mkdirSync` without `recursive`), refuses one that is there and not a real folder (a link to a folder INSIDE the workspace included), writes `RunArtifacts/.gitignore` of `*` with `wx`, and holds the path to the workspace before and after; every file is `wx` with a `-<n>` suffix (`writeNewFile`). `.gitignore` is read back, never trusted (`isFolderWhollyGitIgnored`, the rule the Query tab used): a deploy, retrieve, assign, update, restore, export or generate whose file sits under a RunArtifacts folder that does not ignore everything adds `RECIPE_COCKPIT_RUN_ARTIFACTS_NOT_GIT_IGNORED_NOTE` (`isRunFileExposedToGit`, `withRunArtifactsGitIgnoreNote`) and is at least a warning. **Restore previous values…** lists every run's folder (`resolveTreeSnapshotLocations`: the tree folder's RunArtifacts in the run on screen, then every other run, so a regeneration does not hide a snapshot) and then `treecipe/UpdateAttempts/<folder>/` (`listSnapshots`/`resolveSnapshotFilePath`; a name more than one holds is listed once and resolves to the first). Recipe discovery never reads the folder: `collectRecipeFilePaths` reads two levels and `findTreeRecipeFilePath` the tree folder's own files, so neither reaches it; Run Faker by Recipe's picker skips a directory named `RunArtifacts` (`isRunArtifactsFolderName`), and `findRecipeFilePathRefusal` refuses a recipe path with that segment under GeneratedRecipes. A test helper, `tests/RecipeCockpitRunArtifactsFixture.ts`, builds a location for a suite
