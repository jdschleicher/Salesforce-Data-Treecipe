# Salesforce org service — design notes

Design notes moved out of CLAUDE.md (#563). Read this before changing the service; CLAUDE.md keeps only the rules every change must follow. History is in CHANGELOG.md.

- **Every org picker lists only the authorizations that ANSWER A PING, checked in process, and fails closed** (#201, #502) — the Treecipe tab's picker, Insert Data Set by Directory, Run Picklist Dependency Check and the Dev Hub picker all read `SalesforceOrgService.listConnectedOrgAuthorizations()`, which runs NO process since #502 (`sf org list --json --verbose` and its parser are gone, and so is its entry in `SalesforceCliCallSites.test.ts`). `runOrgConnectionCheck` reads `AuthInfo.listAllAuthorizations()` (`readFreshAuthorizations`, `StateAggregator.clearInstance()` first, #286; a read that throws is `OrgConnectionStatusUnavailableError`, so NOTHING is listed, never every authorization unchecked) and `checkOrgConnections` pings each one, at most `ORG_CONNECTION_CHECK_CONCURRENCY` (5) at a time, the whole listing bounded by `ORG_CONNECTION_LISTING_TIMEOUT_MILLISECONDS` (60 s: an org still unanswered then is `notConnected`, never the list). `checkOrgConnection` never throws: a scratch org whose `isExpired` is exactly `true` (core works it out from the saved `expirationDate`) is `expired` with no request; an authorization core could not read (`error` set) or whose username `isValidTargetOrgIdentifier` refuses is `notConnected` unpinged; anything else is `Org.create({ aliasOrUsername: username })` then `refreshAuth()` (the `HEAD` request `sf org list` pings with; its connection refreshes an expired access token and SAVES it to the CLI's own auth file, as any connection does), raced with `ORG_CONNECTION_CHECK_TIMEOUT_MILLISECONDS` (20 s), and only a resolved ping is `connected`; an `Org` that opens under another username than the one asked for (`Org.create` resolves an alias first) is `notConnected` unpinged. A listing whose own time ran out answers with `isComplete: false` and is NOT cached, so the next picker checks again. There is no Dev Hub `ScratchOrgInfo` query (a decision on #502): a deleted scratch org fails its ping and is `notConnected`, so the `deleted` reason is no longer produced, though the type and counts keep it. A ping asks nothing else of an org: never `logout`, delete or any change (a test proxies the `Org` and holds it to `refreshAuth`). The answer is cached for the extension host's life; two pickers during one check share it; a FAILURE is never cached; `refreshConnectedOrgAuthorizations` (the Treecipe tab's ⟳, and an org the extension creates) replaces the answer, sharing a check already in flight rather than starting a second, and a generation bump keeps a check started before a clear from writing over it. The cache records the authorization usernames read BEFORE the check (`checkedAuthorizationUsernames`): an authorization added since is checked again rather than reported not connected, and a quick pick (no ⟳) that a cached answer leaves empty asks again once — otherwise the warning's own advice, `sf org login web` and try again, could never work. An org is labelled by its own authorization's alias, else its username (the CLI-answer alias fallback went with the CLI). Error text shown in a notification goes through `escapeForNotification`. A suite that lists orgs answers the pings with `SalesforceOrgService/tests/OrgConnectionPings.ts` (`answerOrgConnectionPings`, from `mocks/orgConnectionPings.json`). Quick picks go through `VSCodeWorkspaceService.promptForAuthenticatedOrgDetailOnceListed`, which opens busy with nothing selectable until the listing answers. The Treecipe tab's picker drops its list and selection BEFORE a check, so nothing can be selected or inserted in mid-check, and a stale answer is discarded by `dataOrgRequestSequence` — but it stays DRAWN (#305): the dropdown, ⟳ and + New scratch org stay visible and enabled, a `dataOrgSpinner` sits right of the dropdown, the dropdown's ONE option carries no index (the change handler posts only an all-digit value), and every tree's reason is `RECIPE_COCKPIT_ORG_CONNECTION_CHECK_INSERT_REASON`. That option is `RECIPE_COCKPIT_ORG_LOADING_PLACEHOLDER` until the host posts `dataOrgProvisional` — the org chosen last, else the default, read by `readLocalDataOrgDetail` from the local authorization files AFTER the listing has started, so it never delays the check — which the panel drops for another model, an older check, or once the list arrived. ⟳ stays clickable mid-check; the host joins the check in flight. Once ⟳'s listing answers, the describes of every org it listed are dropped (`clearDescribeCacheForOrg`, #537), and every clear bumps `describeCacheGeneration`, so a describe asked for before it never puts its answer back. While a run holds the selection (`describeSelectionHoldingRun`), `refreshDataOrgs` and `loadDataOrgs` are answered with `dataOrgListingRefused` naming it, never silence: the panel cleared its picker on the click, and `holdDataOrgPickerBeforeCheck`'s snapshot puts it back, but only once every listing it asked for is answered (`dataOrgUnansweredListingCount`), since an earlier ⟳ the host accepted has already dropped its list. No run lock is force-released from the panel; each is released in its run's `finally`. Insert Data Set's free-text alias box is gone: it is a picker like the others
- **`SalesforceOrgLogin` is the one browser login, and the one place the extension WRITES the workspace's default org** (#630) — `authorizeWithBrowser` runs `@salesforce/core`'s `WebOAuthServer` (no `sf` process, so no entry in `SalesforceCliCallSites.test.ts`) against a login address `normalizeLoginUrl` accepted: `https://test.salesforce.com` or an `https://*.my.salesforce.com` origin with no port, path, query or user name, so a typed address can never send the OAuth request to another host. The caller opens the authorization address (the cockpit: `vscode.env.openExternal`) and supplies the cancel; the address carries the client id, state and code challenge, never a token. Core's server has no public stop and no timeout, so a cancel, `ORG_LOGIN_TIMEOUT_MILLISECONDS` (5 minutes) and every other ending close its private `webServer` in a `finally`: left listening it would hold port 1717 (`oauthLocalPort`) and refuse the next login with `PortInUseError`. That reach into a private member is the one coupling to core's internals; it is optional-chained, so a core that renames it only loses the early close. An outcome names the username and nothing else of the `AuthInfo`; a failure message is one line, cut at 300 characters, because it can be the browser request's own `error_description`. The alias is set with `StateAggregator.aliases.setAndSave` after the authorization is saved, and its failure is told, not thrown. `writeWorkspaceTargetOrg` sets `target-org` in `<workspace>/.sf/config.json` directly rather than through core's `Config`, which resolves the project from `process.cwd()`: `.sf` must pass `SfdxProjectService.isPathContainedInWorkspace` (so a linked `.sf` is refused), `config.json` must be a regular file under 1 MB holding a JSON object, a new file is written `wx`, and every other key is kept. Before #630 the extension only read this file, and "+ New scratch org" still creates with `setDefault: false`.
