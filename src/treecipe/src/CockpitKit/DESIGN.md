# Cockpit kit — design notes

Design notes moved out of CLAUDE.md (#563). Read this before changing the service; CLAUDE.md keeps only the rules every change must follow. History is in CHANGELOG.md.

- **The elements every cockpit panel draws with are a kit module, `panel/CockpitPanelElements.ts`** (#638) — `createElement`, `createButton` (typed by `CockpitButtonKind`, and still checking a kind at run time against `COCKPIT_BUTTON_KINDS` for callers in a string), `setShown`, `isMotionReduced`, `setShownWithMotion` and `drawToggle`, plus `SVG_NAMESPACE`. They replace `COCKPIT_KIT_CREATE_BUTTON_SCRIPT` and `COCKPIT_KIT_BUTTON_KINDS_SCRIPT`. The confirmation imports them instead of declaring them, so `COCKPIT_KIT_CONFIRM_DIALOG_SCRIPT_REQUIRES` is down to what only a cockpit has (`vscodeApi`, `renderedSequence`, `focusElement`, the glyph view box and chevron path, and the panel's elements). The reveal and conceal timings are `CockpitMotion.ts`, which imports nothing, so a cockpit's stylesheet and the kit's motion use the same numbers.
- **The confirmation's panel half is a checked module, `panel/CockpitConfirmDialogPanel.ts`** (#637) — it was the `COCKPIT_KIT_CONFIRM_DIALOG_SCRIPT` and `COCKPIT_KIT_CONFIRM_LABELS_SCRIPT` strings. A cockpit takes it by bundling it (the Recipe Cockpit's `panel/RecipeCockpitPanel.ts` exports `renderConfirmRequest` and `closeConfirmDialog`). Its `declare` block is the names it reads from the cockpit script around it; `COCKPIT_KIT_CONFIRM_DIALOG_SCRIPT_REQUIRES` is that block less `confirmDialog`, held to it by `CockpitKit.test.ts`. `confirmDialog` itself stays in `COCKPIT_KIT_CONFIRM_DIALOG_STATE_SCRIPT`, because the Recipe Cockpit's object refresh dialog, still a string, reads it too. The labels and answer shapes are in `CockpitConfirmLabels.ts`, which imports nothing, so the bundle never pulls in `crypto`; `CockpitConfirmDialog.ts` re-exports them.
- **A confirmation can offer record type set modes, and the answer names one** (#623) — a request carrying `recordTypeSetModes` (`{name, label}` each, with `recordTypeSetModeLegend`) draws a `radiogroup` between the body and the buttons, one `check`-kind button per mode with `role="radio"`, the first chosen, all in the Tab cycle. Modes that are not all a name and a label draw none. A chosen button answers `recordTypeSetMode: <name>`; Cancel names none. `CockpitConfirmDialog.readRecordTypeSetMode` gives the name back only when it is one the request offered, and the cockpit that asked reads any other answer as Cancel. Labels are the host's and written with `textContent`. Slice D of #620 offers a second mode through the same group.
